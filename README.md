#  Сервис управления рассылками
Веб‑приложение на Django для создания и запуска email‑рассылок с учётом временных окон отправки, пакетной записью
результатов и кэшированием статистики.

По состоянию на 18.08.2026 проект находится в разработке.

Для отправки писем используется встроенный механизм `django.core.mail`.
Для кэширования статистики - Redis.

Пример ответа от почтового сервера (в виде текста ошибки или «OK»)
сохраняется в поле `server_response` таблицы `SendAttempt`.

## Установка приложения
1. На данной стадии разработки для использования приложения необходимо установить `PyCharm` или любую другую удобную
IDE для Python.
2. Клонируйте репозиторий с [GitHub](https://github.com/Dasha0Ramzer/mailing_service).
3. Создайте и активируйте виртуальное окружение:
```commandline
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate
```
4. Установите зависимости:
```commandline
poetry install
```
5. Убедитесь, что запущен Redis на `localhost:6379`.
6. Примените миграции:
```commandline
python manage.py makemigrations
python manage.py migrate
```
7. Создайте суперпользователя:
```commandline
python manage.py createsuperuser
```
8. Запустите сервер разработки:
```commandline
python manage.py runserver
```

## Разработка
Основные компоненты для работы с рассылками, получателями и сообщениями реализованы в приложении `mailing`.
Логика отправки и пакетного сохранения попыток - в `services.py`.
Права доступа и представления - в `views.py`.

По состоянию на 18.08.2026 в проекте реализованы следующие функции и классы:

**Модуль `models.py` (приложение `mailing`):**

- Модель `Recipient`: хранение списка получателей рассылки.
- Модель `Message`: хранение тем и текстов писем.
- Модель `Campaign`: описание рассылки, включая временные окна (`start_time`, `end_time`), сообщение,
список получателей, владельца и текущий статус.
  - Реализован метод `update_status()` для динамического пересчёта и сохранения статуса в БД
  в зависимости от текущего времени.
  - Валидация временных окон в методе `clean()`.
- Модель `SendAttempt`: запись каждой попытки отправки письма.
   - Поля: `campaign`, `recipient`, `sent_at`, `status`, `server_response`.
   - Поле `server_response` хранит ответ почтового сервера или текст ошибки.

**Модуль `services.py`:**

- Функция `send_campaign(campaign_id)`: запуск рассылки.
   - Выполняет проверку временного окна: отправка возможна только в интервале `[start_time; end_time]`.
   - Формирует список объектов `SendAttempt` в памяти.
   - Использует `bulk_create` для пакетного сохранения всех попыток одним запросом к БД.
   - Сохраняет статус и ответ сервера (`server_response`) для каждой попытки.
   - Возвращает статистику: общее количество, успешные и неуспешные попытки.

**Модуль `views.py`:**

- Представления на основе классов (`ListView`, `CreateView`, `UpdateView`, `DeleteView`) для CRUD‑операций
по получателям, сообщениям и рассылкам.
- Класс `CampaignRunView`: обработка GET/POST для подтверждения и запуска рассылки.
- Класс `CampaignDetailView`:
  - При открытии страницы автоматически вызывает `obj.update_status()`, чтобы статус был актуальным и сохранённым в БД.
- Функция `home`: отображение общей статистики по рассылкам и получателям.
  - Кэшируется на 5 минут с помощью декоратора `@cache_page(300)`.
- Функция `dashboard_view`: персональная статистика пользователя (или общая для менеджера).

**Права доступа:**
- Все представления наследуются от `LoginRequiredMixin`, доступ возможен только авторизованным пользователям.
- Для обычных пользователей показываются только их собственные рассылки и связанные данные.
- Пользователи с флагом `is_staff` видят все рассылки в системе.
